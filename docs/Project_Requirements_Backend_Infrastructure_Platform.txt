Project Title
-------------
Backend Infrastructure Platform (Production-Style Backend Foundation)


Project Goal
------------
Build a production-ready backend platform that demonstrates strong backend 
engineering skills. The system should show understanding of authentication, 
authorization, API design, async processing, caching, observability, 
containerization, and CI/CD — the exact concerns that appear in real-world 
backend systems.


Target Audience (Why This Project Matters)
------------------------------------------
- Backend / Full-stack engineers applying for mid-level or strong junior roles
- Recruiters and hiring managers who look for systems thinking
- Portfolio piece that can be explained deeply in interviews

2. REQUIRED FEATURES (MUST BUILD)
================================================================================

These features are non-negotiable. They form the core of the project.

2.1 Authentication
- JWT-based authentication (Access Token + Refresh Token)
- Token rotation on refresh
- Secure password hashing (bcrypt / argon2)
- Login, Register, Logout endpoints
- Token blacklist / revocation using Redis
- Password reset flow (token via email)

2.2 OAuth
- At least one OAuth provider (Google or GitHub recommended)
- Proper linking of OAuth account with local user account

2.3 Role-Based Access Control (RBAC)
- Roles: Admin, Moderator, User (minimum)
- Permissions attached to roles
- Route-level and service-level guards/middleware
- Ability for Admin to change user roles

2.4 API Gateway Pattern
- Single entry point for all external requests
- Common middleware applied at gateway level:
  - Authentication check
  - Rate limiting
  - Request logging
  - Error formatting
- Internal routing to different modules/services

2.5 Rate Limiting
- Redis-backed rate limiting
- Support for:
  - Per IP
  - Per authenticated user
- Configurable limits (e.g. 100 requests / 15 minutes)
- Proper HTTP 429 response with Retry-After header

2.6 Caching (Redis)
- Cache frequently accessed data (user profile, roles, etc.)
- Cache invalidation strategy
- Use Redis also for:
  - Rate limit counters
  - JWT blacklist
  - Session-like data if needed

2.7 Message Queue (RabbitMQ)
- Asynchronous email sending
- Background jobs
- At least one producer and one consumer/worker
- Proper acknowledgment and error handling
- Dead Letter Queue concept (even if basic)

2.8 Email Queue / Notification Service
- Welcome email on registration
- Password reset email
- Role change notification (optional but good)
- Emails must go through the queue (never send synchronously in request cycle)

2.9 Audit Logs
- Log important actions:
  - Login / Logout
  - Role changes
  - Password changes
  - Billing-related events
- Store: userId, action, IP, user-agent, timestamp, metadata
- Queryable by admin

2.10 Health Checks
- /health endpoint
- Checks status of:
  - PostgreSQL connection
  - Redis connection
  - RabbitMQ connection
- Return proper status codes and detailed response

2.11 Metrics & Observability
- Prometheus metrics endpoint
- Key metrics:
  - HTTP request count
  - Request latency (histogram)
  - Error rate
  - Queue job success/failure
- Grafana dashboard (basic) or at least clear Prometheus queries

2.12 API Documentation
- Full OpenAPI / Swagger documentation
- All endpoints documented with:
  - Request/response schemas
  - Authentication requirements
  - Example values

2.13 Docker & Docker Compose
- Dockerfile for the application
- docker-compose.yml that starts:
  - Application
  - PostgreSQL
  - Redis
  - RabbitMQ
  - Prometheus
  - Grafana (optional but recommended)
- One command to run the entire stack

2.14 CI/CD
- GitHub Actions pipeline
- Stages:
  - Lint
  - Unit / Integration tests
  - Build Docker image
- Optional: push image or deploy step
